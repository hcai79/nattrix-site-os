# Core 40 Internal-Linking Rules

## Purpose

Turn the Core 40 from a page list into a site architecture. Every link should help the visitor take the next useful step and strengthen a clear topical relationship.

## Required link paths

| Source type | Primary destination | Secondary destination |
| --- | --- | --- |
| Informational Post | One relevant Category, Use Case, or Platform Core page | A named review or comparison only when the text naturally supports it |
| Category pillar | Relevant tool reviews | Relevant comparisons and use-case pages |
| Tool review | Its category pillar | Comparisons and realistic alternatives |
| Comparison | Both tool reviews when they exist | Shared category pillar and relevant use case |
| Use-case or platform pillar | Relevant category pillar | Best-fit reviews and comparisons |

## Guardrails

- Use descriptive, varied anchors. Do not repeat exact-match anchor text at scale.
- Add only one primary Core target to a Post unless the content has two genuinely distinct next steps.
- Never add a link solely because a page is commercial.
- Re-check every destination before a live update, especially after content or hierarchy changes.
- Preserve useful existing links unless an audit identifies a specific problem.
